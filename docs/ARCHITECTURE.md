# Architecture and trust boundaries

## Browser pilot

`src/core.js` is the shared synchronous scanner. It returns redacted text and finding offsets/types; it never returns a secret-value field. Repeated detected values are masked within that scan without retaining a lookup table between calls. Overlapping findings merge. A fixed `xxxxx` marker avoids exposing the original length or a reversible mapping. The scanner targets credential formats and labeled values such as keys, passwords, client IDs, client secrets, and tokens; it cannot identify every arbitrary unlabeled secret or confidential passage. Built-in field-name words are compiled with optional horizontal spaces/tabs, underscores, or hyphens between words; case-insensitive matching also accepts joined and camelCase forms. Label boundaries remain enforced. Assignments accept `=`, `:`, `is`, fullwidth `＝`/`：`, nonbreaking horizontal spaces, and a value on the immediately following line. An empty assignment does not consume another labeled assignment on the following line. Straight and curly quotes and Markdown backticks retain value spaces; a missing closing quote masks through the end of the line. Regex capture indices locate exact value offsets, and complete unquoted variable placeholders are preserved. Authorization scheme words do not add a second finding when their following token is already detected, including quoted, backtick-wrapped, or multiline tokens. Incomplete labeled schemes fail closed. Unquoted values stop at whitespace; values containing spaces must be quoted. Separator-free phrases, misspelled names, and grouped field-name/value lists remain outside these assignment rules. Custom labels are escaped literally, and the client-ID setting controls all built-in client-ID variants. The scanner accepts an optional explicit character limit; its default and the stdin filter remain capped at 100,000 UTF-16 characters. Browser guard, Mask, and pre-send re-scan calls use the full current draft length, so the guard does not impose the default character cap or truncate chat text. The existing scan-work limit remains enforced, and a failed scan blocks recognized sending. The website controls how much text its input accepts; this does not expose or increase model context limits. The scanner makes no network or storage calls. `src/index.mjs` exposes it to other JavaScript hosts.

`src/policy.js` loads local preferences and read-only managed policy. Each configured managed field takes precedence and locks the corresponding local control. Invalid/unreadable policy stops scanning and recognized sending rather than silently reverting to a weaker policy. `sensitiveNames` accepts bounded literal labels and escapes them before use; administrator-provided regexes cannot execute.

`src/adapters.js` limits inspection to documented-in-code editor selectors for the three configured hostnames. It does not traverse arbitrary inputs, passwords, login forms, iframes, shadow DOM, attachments, or chat history. Contenteditable updates use a browser editing transaction when available, then emit input to synchronize the page framework. Fallbacks can flatten rich-text formatting. Masked editor text must be verified and re-scanned before automatic submission.

`src/content.js` is injected at document start in the isolated world. Capture-phase listeners gate recognized Enter, send-button pointer/click, and form submission paths. A secret-bearing attempt is canceled and opens a review dialog with a single counted headline such as **2 secrets detected**, with the number in red and **Send**, **Edit**, and **Mask** buttons. The dialog has no explanatory paragraph or footer. It enters from the bottom and exits upward for Send or Mask and downward for Edit; reduced-motion preferences skip the animations. Draft and policy validation run again after exit animation before either sending action. The count describes detected occurrences, not confirmed leaks or exhaustive coverage. **Send** authorizes the current unchanged draft for one submission attempt under the current policy; **Edit** closes the dialog and focuses the unchanged draft without sending; **Mask** writes the redacted text back to the editor and automatically submits that masked prompt once. Masking requires a successful re-scan and revalidation of the current draft and policy before submission. Block mode removes **Send** from the popup, leaving **Edit** and **Mask** under the same validation requirements. The original-send checks still reject block mode even if an old button reference is invoked. Scan/policy failures cannot be overridden through the dialog. Gesture suppression prevents trailing events from duplicating a submission while the dialog opens or the draft is masked. Paste does not scan or change clipboard text; the complete draft is scanned at submission. Status notices disappear after five seconds, with a Lagoon Teal countdown bar along the top. Replacing a notice restarts its timer and bar; deferred notices start when they become visible. Reduced-motion mode updates the bar in one-second steps. Notice dismissal never submits a draft or closes the review dialog.

`extension/composer.html` is the extension-origin protection dashboard. Its main panel adds up to 50 custom field names through a single-line input and Save button using the existing `sensitiveNames` policy. The Save button becomes available after three non-padding characters are entered. The Custom secret fields section starts collapsed, like Protection settings. Expanding it shows the input and saved names automatically below a plain count, newest first, one full-width row per name. Remove icons sit on the right. At 50 names the entry form is hidden and disabled; removing a name restores it. The same limit is enforced by the scanner and managed schema. Duplicate names are rejected case-insensitively. Each save or removal is applied immediately; pending writes disable the mutation controls. The two mode radio choices and client-ID checkbox save changes automatically, without a settings Save button. Field additions, removals, and individual setting updates are sent to the service worker as operations. A shared queue applies each operation against the latest local and managed policy, preserving concurrent changes across views. Failed setting writes restore the saved selection and show an error. Managed values retain precedence and disable the corresponding controls. Names are literal labels, never regular expressions or a secret-value vault. Prompts such as `dataset1 = value`, `dataset1: value`, and `dataset1 is value` trigger the existing review path after `dataset1` is configured. The private compose/copy UI has been removed. The extension page CSP blocks network connections, embedded objects, base-URL changes, and form submission. Source, DM Sans, and icons are bundled locally. The Orbit Pointer image and font are web-accessible only to the three supported chat hostnames; the dashboard and policy files are not.

`src/stats.js` sends only a counter kind and positive integer increment to `extension/background.js`. The service worker serializes writes across tabs and stores three bounded numeric totals in the `activity` key: `detected`, `maskedPrompts`, and `unmaskedPrompts`. Prompt increments are restricted to one and recorded only after the corresponding website send control is activated. An unsent masked draft does not increment a sent-prompt total. Detection is recorded once per new review; repeated attempts count again. Historical detection totals are retained, while the old `masked`, `sent`, and `edited` fields are ignored and removed on the next counter write. Their secret counts cannot be migrated as prompt counts. These counters remain content-free. Activity failures do not interrupt scanning or sending decisions. Activity storage changes refresh the dashboard without reloading policy or replacing unsaved custom field names. Policy changes retain the existing validation behavior. The action still opens the original toolbar popup.

`src/history.js` stores unmasked-send events separately in the extension origin's `ckretguard-history` IndexedDB database. After an approved original submission activates the send control, the content script sends the complete original prompt and detected count to the service worker. The worker requires the extension's sender ID, a top-level tab, and an HTTPS URL on a supported host. It generates the ID and timestamp itself and derives the site and a sanitized conversation link from the browser-provided sender URL, retaining only supported `/c/id` or `/chat/id` paths and removing queries/fragments. It does not accept caller-supplied links or timestamps. Full text is retained without truncation, including prompts longer than 100,000 characters. Failed storage writes report a notice after sending; they do not change the already approved send. Mask, Edit, plain messages, cancelled approvals, and unavailable send controls do not create entries. Events describe activated submission attempts, not provider delivery acknowledgments. No previous chat messages are collected or imported.

History list/delete/clear requests are accepted only from this extension's `composer.html` dashboard. Content scripts have no access to the extension-origin database or its read/delete message operations. The worker serializes policy operations, history operations, and counter updates across tabs; IndexedDB transaction completion acknowledges persistence. Metadata-only change notifications refresh open History views. Listing returns pages of at most 200 metadata records, without prompt bodies. Opening a prompt reads it in bounded 1 MiB text chunks, avoiding Chrome runtime message limits. Clear History remains available if listing fails. `extension/dashboard.js` shows the Home, History, Privacy Policy, and Contact Us navigation only in a full tab, detected through `tabs.getCurrent()`. Toolbar popup layout remains compact. History is newest first, with collapsed prompts rendered using `textContent`, individual deletion, and confirmed clear-all. Deletion does not reset counters or remove provider messages. History is not encrypted, synced, uploaded, or an authenticated enterprise audit log; browser storage limits apply. Entries older than 90 days are physically deleted before History operations, on worker startup, and by an hourly Chrome alarm. Cleanup resumes when Chrome runs; users may delete entries earlier. The alarms permission is used only for local retention cleanup. The UI and privacy text disclose that it contains original secret values.

The content script can still be bypassed by the host page, changed DOM, other extensions, and unobserved event/API paths. The page itself sees typed text. There is no fetch/XHR patching, TLS interception, or DNR body rewriting. Chrome DNR is not a general request-body redaction facility. This UI guard pauses recognized sending paths; it does not prevent the website from reading the input before submission.

## Plugin companion

The private portable plugin contains a setup skill and a copy of the verified extension build. It provides installation and coverage guidance; it does not expose a tool that asks the model to pass raw credentials to a scanner. Calling an MCP scanning tool after a model has read the prompt would be too late for this product's purpose. A plugin listing/install does not establish that the Chrome extension is installed or enabled.

## Other clients

Each additional host needs an independently verified pre-model integration. The core is portable; interception is host-specific.

| Client | Potential integration | Status |
| --- | --- | --- |
| ChatGPT / Claude Chrome websites | Custom field settings + browser event guards | Implemented pilot; fixtures tested |
| Codex / ChatGPT Work local runtime | Trusted local lifecycle hook if the current host supports prompt gating | Research only; not bundled or enabled |
| Claude Code | Local `UserPromptSubmit` command hook with supported blocking/rewrite semantics | Research only; not bundled or enabled |
| Custom AI application | Import scanner before request serialization | Scanner API included; app integration unimplemented |
| Enterprise agent fleet | Approved endpoint/SDK enforcement and central policy distribution | Future work |
