# Architecture and trust boundaries

## Browser pilot

`src/core.js` is the shared synchronous scanner. It returns redacted text and finding offsets/types; it never returns a secret-value field. Repeated detected values are masked within that scan without retaining a lookup table between calls. Overlapping findings merge. A fixed `xxxxxxxxxx` marker avoids exposing the original length or a reversible mapping. The scanner targets credential formats and labeled values such as keys, passwords, client IDs, client secrets, and tokens; it cannot identify every arbitrary unlabeled secret or confidential passage. Built-in field-name words are compiled with optional horizontal spaces/tabs, underscores, or hyphens between words; case-insensitive matching also accepts joined and camelCase forms. Label boundaries remain enforced. Assignments accept `=`, `:`, `is`, fullwidth `＝`/`：`, nonbreaking horizontal spaces, and a value on the immediately following line. An empty assignment does not consume another labeled assignment on the following line. Straight and curly quotes and Markdown backticks retain value spaces; a missing closing quote masks through the end of the line. Regex capture indices locate exact value offsets, and complete unquoted variable placeholders are preserved. Authorization scheme words do not add a second finding when their following token is already detected, including quoted, backtick-wrapped, or multiline tokens. Incomplete labeled schemes fail closed. Bare schemes require token evidence or quoted values; Basic user/password encoding is recognized locally. Ordinary authentication prose and generic unquoted `key/secret is to/that …` instructions are excluded without weakening explicit or quoted assignments. Unquoted values stop at whitespace; values containing spaces must be quoted. Custom labels are escaped literally, and the client-ID setting controls all built-in client-ID variants. Ordered grouped-label/next-line inference has been removed.

An independent whole-draft heuristic is gated by enabled field mentions (built-in spelling variants and plurals, or literal custom names). It runs regardless of direct matches. Specific names allow opaque strings of 12–512 characters; generic key/secret/token mentions require at least 20 characters and stronger evidence. Character variety, Shannon entropy, digit/case/symbol patterns, and readability checks distinguish candidates from ordinary prose and readable identifiers. Recognized values, keyword spans, placeholders, URLs, paths/emails, and clearly labeled public IDs/hashes are excluded from that pass; configured custom names override the public-label exclusions. Explicit opted-out client-ID values are excluded, but unlabeled values cannot reliably be assigned to a client-ID or secret field by position. The heuristic adds `context-secret` finding offsets without value copies. Short/readable indirect values, obfuscation, and unknown formats can still be missed, and false positives remain possible. No dictionary or model is fetched, and no credential is validated against a provider.

The scanner accepts an optional explicit character limit; its default and the stdin filter remain capped at 100,000 UTF-16 characters. Browser guard, Mask, and pre-send re-scan calls use the full current draft length, so the guard does not impose the default character cap or truncate chat text. The existing scan-work limit remains enforced, and a failed scan blocks recognized sending. The website controls how much text its input accepts; this does not expose or increase model context limits. The scanner makes no network or storage calls. `src/index.mjs` exposes it to other JavaScript hosts.

`src/policy.js` loads local preferences and read-only managed policy. Each configured managed field takes precedence and locks the corresponding local control. Invalid/unreadable policy stops scanning and recognized sending rather than silently reverting to a weaker policy. `sensitiveNames` accepts bounded literal labels and escapes them before use; administrator-provided regexes cannot execute.

Gemini targets the Quill textbox inside `rich-textarea`, excluding its clipboard editor. DeepSeek targets its named or branded-placeholder textarea and recognizes labeled send controls plus the observed current and earlier arrow icons; its stop controls are excluded, and its class-only disabled state pauses automatic sending until the framework is ready. Grok targets its query-bar rich-text editor and chat-submit control. Meta AI targets the signed-in `composer-input` Lexical textbox and its textarea variant, filtering out the hidden duplicate composer, plus the guest prompt input and earlier labeled controls. Its `composer-send-button` marker also covers translated Send labels. Text inputs use the appropriate native value setter. The bare `meta.ai` domain shares the `www.meta.ai` adapter. These sites use the existing draft-bound review, masking, and send approval flow.

Microsoft Copilot recognizes its `userInput` textarea and the current `m365-chat-editor-target-element` Lexical editor across its four explicitly allowed browser origins. Perplexity recognizes its `ask-input` rich-text editor and textarea variant on the bare and `www` hosts. Mistral recognizes the ProseMirror composer inside its chat input bar or prompt form on `chat.mistral.ai`; send selectors exclude Stop and Cancel controls. The new sites use the same scanner, review, validated submission, and History. History strips query strings and fragments from supported conversation paths; History derives chatbot identity from the browser-provided sender rather than page-supplied labels.

`src/adapters.js` limits inspection to documented-in-code editor selectors for the 15 configured hostnames. It does not traverse arbitrary inputs, passwords, login forms, iframes, shadow DOM, attachments, or chat history. Contenteditable masking replaces only detected value ranges, from the end of the draft, through browser editing transactions. Rendered offsets are mapped to text nodes so surrounding paragraphs, blank lines, indentation, and unrelated inline formatting remain intact. Each replacement must produce the exact expected visible text; unmappable ranges or rejected edits stop automatic sending. The final input event synchronizes the page framework, and the complete masked draft is verified and re-scanned before automatic submission.

`src/content.js` is injected at document start in the isolated world. Capture-phase listeners gate recognized Enter, send-button pointer/click, and form submission paths. A secret-bearing attempt is canceled and opens a review dialog with a single counted headline such as **2 secrets detected**, with the number in red and **Send**, **Edit**, and **Mask** buttons. Below the headline, the dialog shows the exact detected values without numbered detection labels, plus a short validity note. Values are sliced from the captured draft into text nodes, never HTML or diagnostic metadata. It renders 50 occurrences initially; Show more appends further batches without truncating individual values. The existing dialog scrolls for long lists. Detection types remain internal; the review does not claim credential validity or activity. It enters from the bottom and exits upward for Send or Mask and downward for Edit; reduced-motion preferences skip the animations. Draft and policy validation run again after exit animation before either sending action. The count describes detected occurrences, not confirmed leaks or exhaustive coverage. **Send** authorizes the current unchanged draft for one submission attempt under the current policy; **Edit** closes the dialog and focuses the unchanged draft without sending; **Mask** writes the redacted text back to the editor and automatically submits that masked prompt once. Both sending choices wait up to three seconds for an enabled website Send control, revalidating the draft and policy on each attempt. Mask can follow a framework editor replacement only when there is one visible editor containing the exact verified masked draft. A missing button is allowed to return during that wait; form-only fallback is restricted to the same form that originally triggered review. Activating the control is never retried. One draft-bound approval permits the click and one corresponding form submission, including a deferred callback for up to three seconds; duplicate form callbacks are blocked even after the website clears the submitted draft. Changed input, a new review or gesture, policy changes, and extension teardown cancel the approval. Retired controllers cannot recreate notices when pending work finishes. Masking requires a successful re-scan and revalidation of the current draft and policy before submission. Block mode removes **Send** from the popup, leaving **Edit** and **Mask** under the same validation requirements. The original-send checks still reject block mode even if an old button reference is invoked. Scan/policy failures cannot be overridden through the dialog. Gesture suppression prevents trailing events from duplicating a submission while the dialog opens or the draft is masked. Paste does not scan or change clipboard text; the complete draft is scanned at submission. Status notices disappear after five seconds, with a Lagoon Teal countdown bar along the top. Replacing a notice restarts its timer and bar; deferred notices start when they become visible. Reduced-motion mode updates the bar in one-second steps. Notice dismissal never submits a draft or closes the review dialog.

`extension/composer.html` is the extension-origin protection dashboard. Its main panel adds up to 50 custom field names through a single-line input and Save button using the existing `sensitiveNames` policy. The Save button becomes available after three non-padding characters are entered. The Custom secret fields section starts collapsed, like Protection settings. Expanding it shows the input and saved names automatically below a plain count, newest first, one full-width row per name. Remove icons sit on the right. At 50 names the entry form is hidden and disabled; removing a name restores it. The same limit is enforced by the scanner and managed schema. Duplicate names are rejected case-insensitively. Each save or removal is applied immediately; pending writes disable the mutation controls. The two mode radio choices and client-ID checkbox save changes automatically, without a settings Save button. Field additions, removals, and individual setting updates are sent to the service worker as operations. A shared queue applies each operation against the latest local and managed policy, preserving concurrent changes across views. Failed setting writes restore the saved selection and show an error. Managed values retain precedence and disable the corresponding controls. Names are literal labels, never regular expressions or a secret-value vault. Prompts such as `dataset1 = value`, `dataset1: value`, and `dataset1 is value` trigger the existing review path after `dataset1` is configured. The private compose/copy UI has been removed. The extension page CSP blocks network connections, embedded objects, base-URL changes, and form submission. Source, DM Sans, and icons are bundled locally. The Orbit Pointer image and font are web-accessible only to the 15 supported chat hostnames; the dashboard and policy files are not.

`src/stats.js` sends only a counter kind and positive integer increment to `extension/background.js`. The service worker serializes writes across tabs and stores three bounded numeric totals in the `activity` key: `detected`, `maskedPrompts`, and `unmaskedPrompts`. Prompt increments are restricted to one and recorded only after the corresponding website send control is activated. An unsent masked draft does not increment a sent-prompt total. Detection is recorded once per new review; repeated attempts count again. Historical detection totals are retained, while the old `masked`, `sent`, and `edited` fields are ignored and removed on the next counter write. Their secret counts cannot be migrated as prompt counts. These counters remain content-free. Activity failures do not interrupt scanning or sending decisions. Activity storage changes refresh the dashboard without reloading policy or replacing unsaved custom field names. Policy changes retain the existing validation behavior. The action still opens the original toolbar popup.

`src/history.js` stores unmasked-send events separately in the extension origin's `ckretguard-history` IndexedDB database. After an approved original submission activates the send control, the content script sends the complete original prompt and detected count to the service worker. The worker requires the extension's sender ID, a top-level tab, and an HTTPS URL on a supported host. It generates the ID and timestamp itself and derives the site and a sanitized conversation link from the browser-provided sender URL, retaining only supported provider-specific conversation paths and removing queries/fragments. It does not accept caller-supplied links or timestamps. Full text is retained without truncation, including prompts longer than 100,000 characters. Failed storage writes report a notice after sending; they do not change the already approved send. Mask, Edit, plain messages, cancelled approvals, and unavailable send controls do not create entries. Events describe activated submission attempts, not provider delivery acknowledgments. No previous chat messages are collected or imported.

History list/delete/clear requests are accepted only from this extension's `composer.html` dashboard. Content scripts have no access to the extension-origin database or its read/delete message operations. The worker serializes policy operations, history operations, and counter updates across tabs; IndexedDB transaction completion acknowledges persistence. Metadata-only change notifications refresh open History views. Listing returns pages of at most 200 metadata records, without prompt bodies. Opening a prompt reads it in bounded 1 MiB text chunks, avoiding Chrome runtime message limits. Clear History remains available if listing fails. `extension/dashboard.js` shows the Home, History, Privacy Policy, and Contact Us navigation only in a full tab, detected through `tabs.getCurrent()`. Toolbar popup layout remains compact. History is newest first, with collapsed prompts rendered using `textContent`, individual deletion, and confirmed clear-all. Deletion does not reset counters or remove provider messages. History is not encrypted, synced, uploaded, or an authenticated enterprise audit log; browser storage limits apply. Entries older than 90 days are physically deleted before History operations, on worker startup, and by an hourly Chrome alarm. Cleanup resumes when Chrome runs; users may delete entries earlier. The alarms permission is used only for local retention cleanup. The UI and privacy text disclose that it contains original secret values.

On install/update, the worker reinjects the manifest's scripts and styles into supported top-level tabs using `scripting` and host permissions limited to those same origins. Pages are not reloaded, and drafts are not read or stored by the recovery worker. Content-script controllers use abortable DOM listeners and an isolated-world cleanup function to make reinjection idempotent. Because a reload creates a new isolated world, a DOM handoff event lets only disconnected old controllers retire; connected controllers ignore page-created handoff events. Cleanup clears pending approvals, cancels reviews, removes notices and listeners, and invalidates pending policy loads. The fresh controller loads the current policy before allowing recognized sends. Asset URLs are cached while the runtime is valid so a disconnected controller can still show its refresh notice. An orphan that cannot reconnect blocks recognized sends and old review approvals. Tabs running a build without this lifecycle mechanism need one initial refresh to adopt it. Withheld site access and disabled extensions remain outside recovery guarantees.

The content script can still be bypassed by the host page, changed DOM, other extensions, and unobserved event/API paths. The page itself sees typed text. There is no fetch/XHR patching, TLS interception, or DNR body rewriting. Chrome DNR is not a general request-body redaction facility. This UI guard pauses recognized sending paths; it does not prevent the website from reading the input before submission.

## Plugin companion

The private portable plugin contains a setup skill and a copy of the verified extension build. It provides installation and coverage guidance; it does not expose a tool that asks the model to pass raw credentials to a scanner. Calling an MCP scanning tool after a model has read the prompt would be too late for this product's purpose. A plugin listing/install does not establish that the Chrome extension is installed or enabled.

## Other clients

Each additional host needs an independently verified pre-model integration. The core is portable; interception is host-specific.

| Client | Potential integration | Status |
| --- | --- | --- |
| ChatGPT / Claude / Gemini / DeepSeek / Grok / Meta AI / Copilot / Perplexity / Mistral Chrome websites | Custom field settings + browser event guards | Implemented pilot; fixtures tested |
| Codex / ChatGPT Work local runtime | Trusted local lifecycle hook if the current host supports prompt gating | Research only; not bundled or enabled |
| Claude Code | Local `UserPromptSubmit` command hook with supported blocking/rewrite semantics | Research only; not bundled or enabled |
| Custom AI application | Import scanner before request serialization | Scanner API included; app integration unimplemented |
| Enterprise agent fleet | Approved endpoint/SDK enforcement and central policy distribution | Future work |

Official reference material checked during implementation:

- [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

- [Claude Code hooks](https://code.claude.com/docs/en/hooks)

Do not infer native-client coverage from these references: native adapters have not been built or tested.

Local builds prepare all files before publishing, then replace each destination file with a complete temporary copy using a rename. The `dist` directory is preserved, the manifest is published last, and obsolete files are removed afterward. A failed preparation leaves the previous build intact. This avoids missing or partially copied imports when an unpacked extension reload overlaps a rebuild; it is not a substitute for Chrome's packaged extension update mechanism.

## Production logging

The production branch does not ship a debug logger, log viewer, console wrappers, diagnostic message API, or diagnostic prompt snapshots. Worker startup removes the former `debugLogs` local-storage key and `ckretguard-debug` database. Cleanup failures do not block protection. History remains a separate database with its existing 90-day retention. The development implementation and its tests are retained on `develop`.
